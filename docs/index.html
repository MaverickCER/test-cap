Authentication, owned

Deny by default, at AAL2.

A createAuth call and one line of Express middleware give an app sign-up, sign-in, TOTP, sessions and CSRF protection. The fetch and TanStack Start adapters protect the same way; on Next.js, each route calls the server helper.

test-cap never opens a database connection. It computes each session's assurance level from the evidence that proved it.

Protect every route of an Express app at AAL2 with fewer than 20 lines of setup.

Why it exists

The owner's apps need authentication they can test and patch on their own schedule.

Better Auth, the previous choice, published 49 repository advisories between 2024-12-30 and 2026-11-03, and patches only its latest release. About 180 of its calls read the system clock, and a test cannot replace them.

What an app on it could not do: stay on a release and still receive security fixes, test its own session expiry with a controlled clock — a dependency the app cannot reason about.

  1. What an app on it could not do
    1. stay on a release and still receive security fixes
    2. test its own session expiry with a controlled clock
  2. → a dependency the app cannot reason about

test-cap writes the flows, sessions and assurance rules in one core the owner controls. It leaves each protocol to a library that specialises in it: today, hash-wasm for argon2id.

How it works

One core, thin adapters, the app's own store.

The adapter turns a framework's request into bytes. The core parses, checks CSRF and runs the route against the app's store. The adapter turns the answer back.

A request passes from the framework through a converting adapter to the core. The core reads and writes the app's own store and returns bytes for the adapter to send.

  1. Framework request
  2. → Adapter: converts only; Express, fetch and TanStack Start also apply deny by default with the app's public list
  3. → Core: path check, CSRF, the route, and assurance computed from evidence
  4. → The app's AuthStore: atomic operations over its own database

Because the core makes every decision, a fix to the core reaches every framework at once. Express, fetch, Next.js and TanStack Start adapters exist today; the Nest adapter is in progress and follows phase 4.

The README quick start, answering curl.

The quick start started with APP_ENV=development. Headers are trimmed.

curl -i localhost:3000/account

$ curl -i localhost:3000/auth/session

$ curl -i -X POST -H "Origin: http://localhost:3000" -d "identifier=a%40example.com&password=x" localhost:3000/auth/sign-in

Source: README quick start

/account is not listed as public, so it needs a session at AAL2. A POST without the token from /auth/session is refused before the route runs. A test runs the same quick start and keeps it under 20 lines.

Enforced

What is enforced, and where it stops.

Each claim names what enforces it and where it stops, and links to the decision that defines it.

A route not listed as public needs a session at the default requirement, AAL2.Scope: The Express, fetch and TanStack Start adapters apply it before the app's handler runs. On Next.js, a route is protected when it calls nextServerAuth. A requirement above the default is the app's to check with auth.require inside the handler.Read ADR 0024 ↗
Production refuses to start without HTTPS, a durable store and both keys.Scope: createAuth throws one ConfigError naming every problem. A missing or unknown APP_ENV counts as production. It cannot tell whether a store the app wrote is really durable; it trusts the store's own traits.Read ADR 0026 ↗
Every POST under /auth/ checks a same-origin signal and a synchronizer token.Scope: The signal is an Origin equal to APP_ORIGIN, or Sec-Fetch-Site: same-origin when Origin is absent or null. The app's own routes are the app's to protect; test-cap does not check CSRF on them.Read ADR 0011 ↗
A session's level is computed from evidence that is still valid, and email never raises it.Scope: Password plus TOTP is AAL2. The level drops when the evidence behind it expires. The rules map to NIST SP 800-63B-4; this is not a certification.Read ADR 0005 ↗

Where it fits

Authentication only, next to the other caps.

test-cap answers who a request belongs to and how strongly that was proven. The rest belongs elsewhere.

Which piece handles each concern
Concern Handled by How
Who the person is, and at what level test-cap Ceremonies produce evidence; the session's level is computed from it
What the person may do access-cap (in design) Planned to map its capabilities to test-cap's requirement ids
Shared variables and keys env-cap Documents and validates APP_* and AUTH_* at startup
Accounts, email and kept events The app Its own store, mail sender and event sink

Adoption

From the quick start to every route protected.

Start in development with the memory store, then add a durable store, keys and the routes that stay public.

Route by route, not all at once

  1. Run the README quick start with APP_ENV=development and sign up once by hand.
  2. Start with public: ["/", "/*"], which leaves every existing route open while /auth/* works.
  3. Replace "/*" with the routes that should stay public, one release at a time, then set APP_ENV=production.

Use something else when

The app is not one of the owner's, it needs passkeys, social sign-in or SAML today, or it runs on Nest before that adapter lands.
